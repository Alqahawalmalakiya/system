# القهوة الملكية — نسخة مستقلة على Cloudflare

هذه نسخة منفصلة عن الموقع الموجود في ChatGPT. لا تحتوي على بيانات الاختبار أو بيانات الدخول أو مفاتيح سرية. قاعدة البيانات تبدأ فارغة، وتبقى أسعار المأكولات الافتراضية والشعار والتصميم. حساب Cloudflare وقاعدة البيانات يملكهما صاحب الحساب الذي ينشر النسخة.

تم التحقق من البناء وTypeScript واختبارات توقيع الدخول. يلزم اختبار الموقع والفاتورة على الجوال بعد نشره؛ لم يتم إجراء اختبار بصري للنسخة الخارجية.

## تجهيز الكمبيوتر

1. ثبّت Node.js إصدار LTS من https://nodejs.org/ (الإصدار 22.13 أو أحدث).
2. فك ضغط الملف كاملًا. افتح Terminal / PowerShell داخل مجلد `royal-coffee-cloudflare`.
3. تأكد أن الحساب الذي تستخدمه للنشر هو حساب صاحب النظام. هذه الخطوات تنشئ موارد جديدة، ولا تنقل ملكية الموقع القديم.

الملف يتضمن نسخة مبنية في `dist`؛ لا تحتاج GitHub أو شراء دومين أو تثبيت كل مكتبات المشروع للنشر الأول.

## النشر الأول — الموقع يبقى مقفلًا

نفّذ الأوامر واحدًا واحدًا:

```sh
npx wrangler@4.92.0 login
npx wrangler@4.92.0 d1 create royal-coffee-db
```

المتصفح يفتح لتسجيل الدخول إلى Cloudflare. بعد إنشاء قاعدة البيانات انسخ `database_id` من النتيجة؛ هذا معرّف وليس كلمة مرور.

```sh
node setup.mjs
```

أدخل `database_id` ثم اضغط Enter عند سؤال Access team domain في هذه المرحلة.

```sh
npx wrangler@4.92.0 d1 migrations apply DB --remote --config wrangler.json
npx wrangler@4.92.0 deploy --config dist/server/wrangler.json
```

تطبيق المهاجرات هنا مخصص لقاعدة البيانات الجديدة الفارغة. يظهر رابط `royal-coffee.<اسم الحساب>.workers.dev`. الموقع يعرض رسالة أنه يحتاج إعداد الدخول؛ لا يتيح قراءة البيانات أو تعديلها قبل الإعداد.

## إعداد دخول العميل برمز البريد

1. من Workers & Pages افتح Worker باسم `royal-coffee`، ثم Settings وابحث عن حماية Cloudflare Access للرابط workers.dev. فعّل Access. إن ظهرت خطوات إنشاء Zero Trust، أكملها بالخطة المجانية المتاحة لحسابك واسم فريق تختاره؛ راجع أي شاشة تكلفة قبل الموافقة.
2. افتح تطبيق Access الخاص بالموقع في Zero Trust > Access controls > Applications. استخدم Self-hosted application يغطي عنوان الموقع كاملًا وجميع مساراته، وليس صفحات محددة.
3. أنشئ سياسة Allow تشمل **إيميل العميل المحدد فقط**. لا تختَر Everyone أو Bypass. اجعل One-time PIN ضمن طرق تسجيل الدخول. العميل يستقبل رمزًا على بريده ويستخدمه للدخول.
4. انسخ Team domain مثل `https://your-team.cloudflareaccess.com` وApplication Audience (AUD) من إعدادات التطبيق.
5. نفّذ `node setup.mjs` مرة أخرى: أدخل معرّف قاعدة البيانات نفسه ثم Team domain ثم AUD ثم إيميل العميل.
6. انشر النسخة المعدلة:

```sh
npx wrangler@4.92.0 deploy --config dist/server/wrangler.json
```

حتى إذا أمكن تجاوز بوابة Access أو إرسال ترويسات مزورة، يتحقق Worker من توقيع رمز Access والجمهور وتاريخ الصلاحية والإيميل المعتمد قبل تشغيل صفحات النظام وواجهات البيانات. لا تعتمد النسخة على حساب ChatGPT.

## فحص التسليم

- افتح الرابط من نافذة خاصة: يجب طلب الدخول ومنع أي إيميل غير معتمد.
- سجّل بإيميل العميل، وأنشئ حجزًا تجريبيًا وفاتورة مأكولات.
- أعد تحميل الصفحة وافتح من جوال للتأكد من حفظ الحجز.
- جرّب العسل نصف كيلو: 75 ريالًا، والسمن نصف كيلو: 55 ريالًا.
- تحقق من زيادة كمية الأكلات بالواحد، والطباعة وPDF بالعربية، وتغيير حالة المناسبة.
- جرّب زر تسجيل الخروج، وافتح الرابط مجددًا.
- بيانات الفواتير والمبالغ بالهللات داخل القاعدة. لا تغير قيمها يدويًا إلى الريالات.

## النسخ الاحتياطي والاسترجاع

زر النسخة الاحتياطية داخل النظام يصدّر الحجوزات وقائمة الأسعار JSON للاحتفاظ بها. نسخة الاستعادة الكاملة لقاعدة البيانات تكون SQL:

```sh
npx wrangler@4.92.0 d1 export DB --remote --config wrangler.json --output=backup.sql
```

احتفظ بنسخة SQL خارج حساب الاستضافة. لا تضعها في GitHub أو داخل الملفات العامة. لاستعادة نسخة كاملة، أنشئ قاعدة جديدة فارغة واستورد SQL عليها قبل تغيير ربط DB؛ لا تستورد نسخة كاملة فوق قاعدة مستخدمة:

```sh
npx wrangler@4.92.0 d1 create royal-coffee-restore
npx wrangler@4.92.0 d1 execute royal-coffee-restore --remote --file=backup.sql
```

اختبر الاستعادة قبل اعتماد خطة النسخ الاحتياطي. بعدها حدّث معرّف القاعدة في إعداد النسخة واربطها بالقاعدة المستعادة ثم انشر. أداة setup تحدث المعرف؛ عند إعادة تسمية قاعدة جديدة حدّث database_name كذلك.

## التذكيرات

إضافة المناسبة لتقويم الجوال والمشاركة اليدوية على واتساب موجودتان. الملخص التلقائي في ChatGPT لا ينتقل إلى هذه النسخة، ولا يُعد مُفعّلًا هنا. نحتاج إعداد قناة مستقلة مثل Telegram أو خدمة بريد وتشغيل جدول يومي في حساب العميل لاحقًا. لم نربط خدمة رسائل ولم نرسل رسائل من هذه الحزمة.

## تعديل الكود لاحقًا

```sh
npm install
npm run check
node --test tests/access.test.mjs
npm run build
npx wrangler@4.92.0 deploy --config dist/server/wrangler.json
```

أعد البناء بعد أي تعديل على الكود. بعد إعداد بيانات Cloudflare، يحتفظ build بالإعدادات في wrangler.json. الملف المبني المرفق مخصص للنشر الأول فقط؛ لا تنشره بعد تعديل الكود دون إعادة البناء.

المراجع: https://developers.cloudflare.com/workers/vite-plugin/get-started/ و https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/
